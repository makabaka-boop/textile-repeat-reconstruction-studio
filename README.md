# 织物样片修复工作台（离线纯前端）

修复师导入受污织物样片的 `rows` 数组，工作台只依据**仍可见的经纬纹样**判定
**可唯一证明的最小重复单元**，并补全污点格；无法证明时明确报告
`NO_UNIQUE_REPEAT`，绝不把未知格猜成看似更小的花型。

## 判定规则

设样片为 H × W，候选单元为 tileH × tileW：

1. `tileH | H` 且 `tileW | W`（高、宽分别整除样片尺寸）；
2. 同一模位 `(i mod tileH, j mod tileW)` 上的所有**已知**字符必须一致；
3. 每个模位在整个样片中**至少出现一次已知字符**——否则该格颜色无证据，候选不成立。

在全部可唯一重建候选中，按 **面积最小 → 高度较小 → 宽度较小** 选取，顺序为全序，结果唯一。
找不到任何候选时输出 `NO_UNIQUE_REPEAT`：

- 整尺寸候选（每个模位只出现一次）不可能冲突，因此最终无法恢复的根因必然是：
  某个最小的**无模位冲突**候选里仍有模位从未出现已知字符（颜色被完全擦除）；
- 更小候选上的模位冲突只说明那些尺寸不可能，界面会一并报告数量。

## 导入约束

- 2–300 行，每行 2–300 字符，等长；
- 字符仅允许 `A-Z` 与未知符 `?`；
- 总格点 ≤ 50000；
- 支持 JSON 数组（`["AB","?B"]`）或每行一条字符串。

任何结构错误都**拒绝整份数据**，编辑器保留上一次合法样片，可一键恢复。

## 编辑即失效

在画布上点选格并按 `A-Z` / `?`（或用调色板、Backspace）改色后，
**旧结论立即撤销**，画布与来源列表清空，必须重新判定；
因此画布展示与 JSON 下载永远来自同一次判定结果（载荷带 FNV-1a 指纹便于核对）。

下载 JSON 的坐标为 1 基，包含：重复单元、补全样片、每个被补格的字符与来源模位、
候选统计、指纹。

## 开发与运行

```bash
npm install
npm test        # Vitest：独立枚举 oracle 对拍 + 边界场景
npm run dev     # 本地开发
npm run build   # 类型检查 + 产物构建

docker compose up --build   # 静态托管于 http://localhost:8080
```

## 测试覆盖

`src/lib/pattern.test.ts`：

- 小网格**枚举所有整除尺寸**，与独立 oracle（按模位收集字符集合）逐候选对拍；
- 7 种尺寸 × 多组随机网格（含冲突、全未知行、无证据模位）全候选对拍；
- 全未知样片、冲突模位、模位被完全擦除、横纵周期并列（2×3 vs 3×2）、
  无小周期时回退整尺寸；
- 补全严格周期性、fills 坐标/来源模位正确性、导出坐标与指纹。

## 技术栈

TypeScript + React 18 + Vite（纯静态产物）、Vitest、Docker Compose（nginx 托管）。
无外部字体/CDN/接口，构建后可完全离线运行。
